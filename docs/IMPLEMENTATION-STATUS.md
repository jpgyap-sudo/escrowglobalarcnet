# Implementation status · Escrow Global Settlement 0.3.0
Checked 2026-09-14. This table distinguishes executable work from configured or missing integrations.

## Implementation progress · 2026-09-14

- **SE1a reference quote:** Added `packages/custody-contracts/reference-quote.mjs` as a strict, deterministic, reference-only funding quote. It derives each 3% reserve from principal, preserves USDC/USDT separation, checks u64 bounds, and intentionally cannot sign, broadcast, deploy, or move funds.
- **UX-T1 visual guidebook:** Added accessible inline SVG diagrams and a guidebook introduction for 23 walkthroughs covering plain-language Solana escrow and production-readiness explanations, first-deal, fee/refund math, planned PDA/non-custodial model, goods, on-ramp, external swap, wallet QR, Jupiter Spend registration/KYC/card, merchant QR, scope, and Action Center workflows. The diagrams explicitly distinguish wallet actions from escrow funding and repeat the no-live-custody boundary.
- **UX-T2 deal-room readiness:** Added a four-stage Terms → Funding → Delivery → Settlement path with actor-specific next-step guidance and responsive styling. It is informational only and never changes state.
- **UX-T3 terms history:** Added an expandable, read-only milestone history showing accepted prior terms beside the active scope, checklist, deadline, and retained principal. It is informational only and never changes state.
- **SE3 custody boundary:** Added a compileable Anchor 0.31.1 Solana program under `packages/custody-contracts/program`. The current safety slice constrains a single PDA vault to a buyer/agreement/mint, requires seller acceptance before funding, stores the terms and delivery commitments, commits bounded funding/delivery/review deadlines, reserves the exact 3% platform fee with a `u128` intermediate, restricts custody to the original SPL Token program, requires bilateral refund signatures, supports safe pre-funding cancellation and post-settlement rent recovery, and orders seller principal before fee claim. It is not deployed, audited, or connected to the web API.
- **SE3/V2 multi-milestone boundary:** Added source for a bounded multi-milestone protocol using one `MultiEscrow` account and one independently funded `MilestoneV2` PDA/vault per milestone (maximum 16). Each milestone has its own deadlines, submission/approval/dispute path, fixed-arbiter full release/refund, bilateral refund, independent claims and close. The V2 client-intent surface, fresh ABI, and isolated native lifecycle execution are verified; SBPF runtime execution, live-cluster deployment, audit, and production adapter remain gated.
- **SE5 journal/reconciliation aid:** Added a separate fsynced, hash-linked JSONL operation journal with canonical JSON, integrity verification, state hashes, bounded cursor pagination, and read-only admin journal/reconciliation endpoints. This improves sandbox auditability and crash diagnosis; it is not a replicated PostgreSQL ledger or chain indexer.
- **SE1 intent hardening:** The unsigned custody-intent builder now derives reserves from principal, requires a network-qualified deployment manifest (program ID, genesis hash and fixed fee recipient), validates Solana address shape and supported networks/token programs, rejects placeholder terms commitments, binds the funding signer to the buyer, and exposes signer/state-bound intents for the current Anchor instruction names. It remains unsigned and non-broadcastable.
- **SE6 transaction UX foundation:** Added a side-effect-free transaction-attempt state machine for draft → wallet signature → submitted → confirmed → finalized, with explicit failure/expiry retry rules, durable serialization, and tests. It prevents UI callbacks from being treated as signatures or finality; RPC/wallet integration remains gated.
- **SE7 readiness gateboard:** Added a machine-readable `/api/custody/readiness` response that exposes every live-custody blocker instead of relying on a hidden flag. The endpoint always reports sandbox/no-real-funds until deployment, audit, production auth/storage, RPC reconciliation, operations and legal approval are explicit.
 - **SE8 reconciliation boundary:** Added a pure, exact-integer verifier plus a dependency-injected RPC worker for a future normalized Solana funding observation. It requires finalized status, a finalized program-owned base64 agreement account, the original buyer signer/token-account owner, exact program/agreement/mint/token/vault/amount bindings, the exact `fund`/`fund_milestone_v2` discriminator and account order, exactly one parsed transfer, and idempotent operation IDs. It now includes strict V1/V2 Anchor account-prefix decoders that verify account ownership and discriminators before extracting agreement commitments, resolves versioned-transaction loaded addresses, requires the configured RPC endpoint to return the exact deployment-manifest `getGenesisHash` value before loading evidence, requires account context at least as new as the funding transaction, carries the verified transaction slot into evidence, and exposes finalized raw-vault projection wiring; production authentication, database deployment and wallet/API integration remain required, and the worker cannot sign or broadcast.
- **SE8 mint-admission hardening:** Reconciliation and unsigned custody intents now require a network-qualified admitted-mint allowlist; a correctly hashed intent cannot cause an arbitrary SPL mint to be credited by the future worker.
 - **SE20 dependency-injected SDK boundary:** Added `packages/escrow-sdk/index.mjs`, a pure adapter that derives canonical V1/V2 PDAs and encodes exact Anchor instruction specifications for every current Rust instruction, including Common Ground, timeouts, cancellation, claims and close paths. `operation-boundary.mjs` adds an explicit fee-payer/signer/canonical-account/writable-account/action/data gate before wallet handoff. It pins the program/network/genesis-hash/mint/legacy SPL Token/fixed fee recipient and cannot fetch accounts, construct transactions, sign, submit, or mutate funds; it is not yet the production wallet/API adapter.
 - **SE21 read-only RPC transport:** Added `src/custody/solana-rpc.mjs`, a native fetch-based JSON-RPC adapter with HTTPS enforcement for public clusters, loopback-only localnet HTTP, bounded timeouts, strict response validation, and only finalized-read methods. It cannot send transactions or access wallet keys.
 - **SE22 bilateral terms amendment:** Added V1 `amend_terms` and V2 `amend_terms_v2` instructions plus SDK/intent builders. Buyer and seller must sign together; only pre-funding amendments are allowed, the seller's acceptance is reset, and funded agreements cannot mutate their terms commitment.
 - **SE23 fee-recipient consent:** The deployment ceremony requires the fee recipient to sign the immutable deployment configuration; agreement initialization no longer accepts a caller-supplied fee destination.
 - **SE24 empty-vault funding guard:** V1 funding now rejects any pre-existing vault balance, matching V2 and preventing direct-transfer donations from being silently mixed with the canonical funding amount.
 - **SE25 role-consent hardening:** Both agreement initialization instructions require the fixed arbiter to sign; the fee recipient is read from the immutable deployment configuration.
 - **SE26 reconciliation wiring:** V1 and V2 RPC reconciliation now use strict built-in Anchor account decoders when no decoder is supplied. V2 requires both finalized parent and milestone accounts, verifies the parent link/index, and binds the independently supplied milestone vault PDA.
 - **SE27 multi-party intent hardening:** Multi-signature amendment, bilateral-refund, and Common Ground remainder intents now reject an unrelated authorization signer instead of relying only on the downstream required-signer list.
 - **SE28 account-boundary hardening:** Finalized reconciliation account loads now require valid Solana addresses, `executable: false`, program ownership, canonical base64, and the loaded account PDA must match the decoder result.
 - **SE29 evidence replay boundary:** The local operation journal now provides an idempotent custody-evidence append path keyed by `operationId`, returning the original record for an identical replay and failing closed on conflicting evidence. It is process-safe only for the local journal; production still requires a transactional replicated store with a unique operation key.
 - **SE30 terminal-ledger invariant:** Every full V1 cancellation, refund, approval, timeout, and fixed-arbiter outcome now clears `unresolved_principal`; the source-level regression suite covers every full-outcome handler so terminal records cannot retain a stale unresolved balance.
 - **SE31 on-chain terms proof:** Reconciliation decoders now extract the persisted V1/V2 `terms_hash` and require it to equal the unsigned funding intent commitment. V2 vault ownership is bound to the milestone PDA rather than incorrectly assuming the parent escrow PDA; regression coverage includes forged terms and authority cases.
 - **SE32 V2 late-refund completeness:** Added the missing buyer-only `claim_milestone_late_refund_v2` path and matching SDK/intent support. It refunds the exact on-chain expected total only after a funded milestone misses delivery without submission; the V2 aggregate close intent now requires every milestone to be closed or cancelled.
- **SE9 agreement preflight:** Added an advisory, deterministic agreement checker in the creation modal. It flags missing scope, acceptance, deadlines, invalid amounts, vague criteria and workflow-specific omissions without inventing a safety score or blocking funds on model output.
- **SE10 operator readiness surface:** Added a responsive, brand-aligned custody gateboard to the local operator console. It distinguishes a local Anchor artifact from an actually deployed program and makes every remaining live-custody blocker visible without adding an enable switch.
- **SE11 server-route verification:** Fixed the server-side static module map so the local server serves the tutorial visual module used by the application, and added HTTP regression coverage for that route and the operator stylesheet.
- **Common Ground:** Added a deterministic non-signing calculator plus a bounded on-chain proposal/approval/execute/remainder slice. It is not yet a complete multi-round dispute protocol or production deployment.
- **Dispute arbiter slice:** The Anchor program now supports an explicit original-party dispute transition and fixed-arbiter all-seller/all-buyer resolution without arbitrary split destinations. Opening a dispute atomically charges a separate, non-refundable 5% fee from the opener to the fixed fee recipient; backup resolver phases remain unimplemented.
- **SE12 artifact freshness:** The readiness endpoint now compares local SBF/IDL artifact timestamps with the current Rust source and labels stale output as requiring a rebuild; it never treats artifact presence as deployment evidence.
- **SE13 legacy-token runtime boundary:** The custody crate disables Anchor SPL default features and uses `Program<Token>`/legacy `TokenAccount` types. Anchor 0.31's generated `token::` initializer also needs the `token_2022` feature to compile its account-sizing branch, but Token-2022 mints/accounts remain rejected by the program's runtime account owners and constraints.
- **SE14 bounded chain-time intent deadlines:** Initialize intents now carry explicit funding, delivery, and review deadlines, enforce a bounded horizon and review window, and support an opt-in timed-release flag without signing or broadcasting transactions.
- **SE15 rights, evidence and receipt UX:** Deal rooms now show the next action owner, permitted action, deadline and fallback caveat; disputed milestones expose a criterion-by-criterion evidence guide with explicit missing-verification warnings; users can export a privacy-conscious, clearly labelled sandbox protection receipt or copy a sandbox-only deal link. None of these surfaces proves chain settlement or authorizes a payout.
- **SE16 fee-sponsorship education boundary:** Added a visual tutorial explaining how a future fee sponsor must remain separate from the original signer, use instruction allowlists and caps, and preserve idempotent retries. The sandbox has no sponsored Solana transactions and still discloses the prototype dispute charge.
- **SE17 support-before-dispute path:** The resolution center now offers a clearly labelled free support-guidance route before the paid prototype dispute action. It does not alter dispute balances or create formal case authority; production access, staffing and fee policy remain open decisions.
 - **SE18 ProgramTest dependency isolation:** Moved the lifecycle `ProgramTest` harness into an excluded, independent workspace with its own lockfile boundary so the deployable SBF workspace resolves only the custody program's Anchor dependencies. Both manifests have valid locked no-dependency metadata, the deployable program now compiles and its seven native Rust tests pass on Windows, while the isolated lifecycle workspace still cannot run offline because `solana-accounts-db` is not cached and online crates.io resolution timed out. Docker Desktop's Linux engine is also unavailable.
- **SE33 independent recovery boundary:** Added `packages/escrow-recovery`, a login-free Escrow Passport verifier that accepts only finalized owner/state-verified evidence, pins deployment/mint identity, checks milestone conservation and entitlements, and exposes exact claimable amounts without signing or submitting transactions.
- **SE34 CPI ordering hardening:** V1/V2 dispute and claim handlers now stage state, entitlement and dispute-fee ledger transitions before legacy SPL Token CPIs; failed CPIs roll the whole transaction back, and source-level tests protect the ordering.
 - **SE35 ABI regeneration:** Added `scripts/generate-custody-abi.mjs` to regenerate the Anchor IDL and TypeScript helper from the pinned private IDL test output without the Anchor CLI. The ABI at that slice contained 42 instructions and 25 events and passed source/address parity; later lifecycle additions expanded the ABI, while verification still rejects the stale SBF binary.
- **SE36 transaction ambiguity:** Added an explicit `unknown` transaction-attempt state for post-submit RPC ambiguity. It preserves the signature and reason, blocks blind retry, and requires reconciliation before resolution to confirmed/finalized or a terminal failure.
- **SE37 durable lifecycle validation:** Transaction-attempt deserialization now replays legal transitions and retry attempt numbers, requires an initial draft/current-history match, and rejects inconsistent failure metadata.
- **SE38 journal writer serialization:** Local journal mutations now use an exclusive lock around verification, idempotency lookup and append, preventing concurrent writers from racing sequence/hash-chain state; lock contention fails closed.
 - **SE39 strict PDA and snapshot verification:** Reconciliation now recomputes canonical V1 escrow/vault and V2 escrow/milestone/vault addresses from stored seeds instead of trusting account labels. V2 parent and milestone reads use one finalized `getMultipleAccounts` snapshot, and the read-only RPC adapter exposes that method; forged addresses and mixed-slot evidence are rejected.
 - **SE40 lifecycle harness signer parity:** The isolated ProgramTest fixture now initializes the deployment config separately with authority/fee-recipient consent, then supplies only the buyer/arbiter signatures required by agreement initialization.
 - **SE41 fail-closed chain worker:** Added `src/custody/chain-worker.mjs` to normalize reconciliation outcomes into verified, pending, unknown, failed, or rejected states. It never signs or broadcasts, replays committed evidence by logical `operationId`, ignores caller-supplied recorders, and refuses to treat inconclusive provider errors as permission to request a new signature.
 - **SE42 recovery PDA proof:** The login-independent Escrow Passport verifier now recomputes the canonical V2 agreement, milestone and vault PDAs from the deployment program, buyer, commitment and milestone index. Forged account labels are rejected before a recovery claim view is produced.

A provider that accepts a request but never returns JSON cannot hang reconciliation indefinitely; the adapter returns its typed timeout error and remains non-broadcasting.
 - **SE44 provider quorum boundary:** Added an opt-in read-only RPC quorum adapter requiring at least two complete, explicitly distinct provider identities to agree exactly on genesis, signatures, transactions and account snapshots. Any provider failure, duplicate provider identity or disagreement becomes `QUORUM_MISMATCH`; no single response is silently trusted.

 - **SE46 lifecycle timestamp integrity:** Transaction-attempt transitions, retries, and durable replay now reject timestamp regression, preventing a forged or out-of-order local history from appearing newer than a prior state change.

Cross-table fee/mint admission is enforced by a database trigger; raw evidence bytes and secrets are excluded.
 - **SE49 immutable deployment policy:** Added an on-chain `DeploymentConfig` PDA and one-time `initialize_config` instruction.
